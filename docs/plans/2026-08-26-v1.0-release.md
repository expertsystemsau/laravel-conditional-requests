# v1.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn a working package into a releasable one. Three deliverables and nothing else: documentation a stranger can succeed with, a migration guide off `werk365/etagconditionals`, and an API freeze that is enforced by a test rather than promised in prose.

**Architecture:** No runtime feature changes. The README is cut back to an entry document and the reference material moves into eight `docs/` pages, one of which — `docs/hazards.md` — is a numbered register with stable anchors that every other page links into. The public API is named exhaustively in `docs/api.md` and pinned by a reflection snapshot test, so adding, removing, or changing any public signature fails the suite until someone updates the frozen list on purpose. Two public surfaces are cut before the freeze rather than carried for ever.

**Tech Stack:** PHP 8.3–8.5, Laravel 12–13, Pest 4/5, Orchestra Testbench, PHPStan level 7, Pint.

**Spec:** `docs/design/2026-08-25-conditional-requests-design.md` — §6 (configuration), §7 (edge cases), §9 (phasing), **§10 (non-goals)**, **§11 (werk365 parity, the 13-defect table in §11.2, and the cutover differences in §11.3 — the backbone of Task 7)**.

**Builds on:** the completed end state of `docs/plans/2026-08-26-v0.3-write-path.md`, `docs/plans/2026-08-26-v0.4-last-modified.md`, and `docs/plans/2026-08-26-v0.5-locking.md`. By the time this plan starts the package has: body-hash and model-derived validators, the pre-controller short-circuit, the full write path (`If-Match` → `412`, `required` → `428`, the `If-None-Match: *` create guard), the `Last-Modified` family (`Last-Modified`, `If-Modified-Since`, `If-Unmodified-Since`), and opt-in `lock` mode with in-transaction re-evaluation. Every task below assumes all of that is shipped, green, and documented at the level each of those plans left it.

**Adversarial input:** `integration-findings-v02.md` — a hostile sweep of ~240 requests across 11 middleware-arrangement families against a real Laravel 13 app. Its findings F1, F3, F4, F5, F6, F7 and F8 are hazards the documentation must carry; **F2 was closed in code by commit `f748bb7` and must not be documented as live** (Task 11 checks this).

## Global Constraints

- PHP `^8.3`; Laravel `^12.0||^13.0`. The PHP 8.3 floor means `(new Foo)->bar()`, never `new Foo()->bar()`. Pint's Laravel preset strips empty constructor parentheses in this repo — write `new Response`, not `new Response()`.
- **No new runtime dependencies, and no new runtime features.** Every task here writes documentation, tests, CI, or removes public surface. The only `src/` edits this plan makes are docblock annotations, one `final`, and one deletion.
- Every `src/` file starts with `declare(strict_types=1);` — enforced by `tests/ArchTest.php`, whose rule targets the whole `ExpertSystems\ConditionalRequests` namespace, so **test fixtures under `tests/` need it too**.
- `dd()`, `ddd()`, `env()`, and `exit()` are banned everywhere, tests and config included — enforced by `tests/ArchTest.php`. Inside `src/`, config is read through the injected `Illuminate\Contracts\Config\Repository` and translations through the injected `Illuminate\Contracts\Translation\Translator` — never the `config()` or `__()` helpers.
- Config key namespace and publish tags stay `laravel-conditional-requests*`. **v1.0 adds no config keys and removes none.**
- Root namespace is `ExpertSystems\ConditionalRequests\`.
- Type coverage gate is 100% (`composer test:types`); PHPStan runs at level 7 over `src` and `config` only. **The type-coverage plugin silently skips any file containing the string `trait `**, so `src/Concerns/HasConditionalValidator.php` is covered by PHPStan alone and a green `test:types` is not evidence about it. Task 9's snapshot test reflects the trait's frozen members through a fixture class that uses it, which is the only way to assert them.
- Commit subjects match the existing history style — sentence case, imperative, no `feat:`/`fix:` prefixes.
- **Every test green at the end of v0.5 must stay green.** Two exceptions, both created by Task 8's facade removal and both mechanical: the four test files that call `ConditionalRequests::extend()` statically are rewritten to call it on the container-resolved registry. No assertion changes.
- **Every documentation claim must be verifiable against the code.** Where a task below says "write X", it names the fact and the symbol that makes X true. A writer who cannot find the symbol must stop and report, not paraphrase. Task 11 re-checks the whole set.

## Design decisions settled before planning

Restated because most tasks depend on them and a worker should not re-litigate them mid-task.

### D1 — What lives in the README, and why

The README answers three questions and no more: **what is this**, **does it apply to me**, and **how do I get one route working**. Everything a reader needs only *after* deciding to use the package — the configuration reference, tag scoping, custom strategies, `lock` semantics, placement rules, migration — is a `docs/` page.

There is exactly one exception, and it is deliberate: **the hazard summary stays in the README.** The cost of a reader not meeting those hazards is paid by *that reader's users*, not by the reader, so the usual "link it and trust them to follow" rule does not apply. A link that is never followed is not a warning.

The README has grown by accretion across four phases and currently runs 357 lines with four `[!WARNING]` blocks, three `[!IMPORTANT]` blocks, and six `[!NOTE]` blocks interleaved with the tutorial. After v0.3–v0.5 it will be longer again. The failure mode is not that the warnings are missing; it is that a reader who skims the parts relevant to them will miss the ones that are not adjacent to what they are reading.

### D2 — Hazards get a register with stable anchors, not a wall of warnings

Four devices, applied together. Task 2 builds the register; Tasks 3–6 wire the other three.

1. **A six-line block in the README**, immediately after the quickstart and before anything else. Consequence first, mechanism never, one link each.
2. **`docs/hazards.md`** — a numbered register, `H1`…`H18`, each with a stable `#h<n>` anchor that never changes even if the ordering does. It opens with a scan table whose middle column is *"You are exposed if"*, so a reader can decide which entries apply without reading one.
3. **In-context callouts.** Every topic page repeats the one-line consequence and links to the anchor at the exact point the feature is introduced, so a reader who arrives at `docs/writes.md` to use `lock` meets H9 there rather than hoping to have read the register first.
4. **A symptom index** at the foot of the register — *"304s work locally and never in production"* → H8, H11; *"a client sees stale data"* → H3, H5, H7; *"the controller runs on every request"* → H11 — so someone who arrives with a symptom rather than a question lands on the cause.

### D3 — The freeze is a test, not a promise

A prose list of public API is a list that drifts. `docs/api.md` states the contract for humans; `tests/Feature/PublicApiTest.php` states it as a sorted `list<string>` of reflected signatures and fails when the two disagree. Any addition, removal, or signature change breaks the suite until someone edits the frozen list, which is the moment the semver decision gets made. That is worth more than a docblock convention, and the repo already runs Pest arch tests, so the machinery is there.

Everything not on the frozen list carries `@internal`, and that too is asserted rather than trusted.

### D4 — Two public surfaces are cut before the freeze

No tags exist. Nothing has ever been published to Packagist. This is the last moment at which removing something costs nothing, and two things should go. Task 8 sets out the reasoning in full; the decisions are:

- **`Facades\ConditionalRequests` is deleted**, along with its `extra.laravel.aliases` entry. It fronts a two-method registry, one of which is only ever called by the middleware, so its real surface is a single boot-time call — and a facade makes that call frictionless from exactly the places the README already forbids.
- **`ModelStrategy::lockingQuery()` is marked `@internal`** and v0.5's claim that an application can override it is corrected. The class is `final readonly`; nothing can override anything on it. Decoration through `LockableValidatorStrategy` is the supported route and gets a worked example.

### D5 — The changelog is collapsed, and `UPGRADING.md` is not created

No 0.x version was ever tagged. The `## [Unreleased]` compare link currently points at `compare/v0.1.0...main`, which 404s, because `v0.1.0` does not exist. Presenting `## v0.1.0` as released history is a false claim in the one file whose entire job is to be accurate about releases.

So the 0.x sections collapse into a single `## v1.0.0`. The per-phase detail is not lost — it lives in `docs/plans/`, which is in the repository.

`UPGRADING.md` is **not** created at 1.0, because there is no released version to upgrade from and a file whose content would be "there is nothing to upgrade from" is worse than its absence. The rule that creates one is added to `CONTRIBUTING.md` and to the release checklist instead: the first change that breaks the frozen surface opens it.

- [ ] **Step 3: Write the eighteen entries**

Under `## The register`, write one `### H1 — <title>` … `### H18 — <title>` section per row, in the four-part shape from Step 1. The facts below are what each entry must be built from. **Do not invent beyond them.** Where a "Verified by" is given, name it in the entry so a reader can go and read the proof.

**H1 — A pre-controller `304` answers before anything declared after `conditional`.**
Fact: `Conditional::handle()` returns the response built by `notModified()` *before* it calls `$next($request)`. Everything after `conditional` in the stack — `can:`, `signed`, a subscription gate, a custom tenant check, a rate limiter that is not on Laravel's `$middlewarePriority` list — never runs on a hit, and neither does a per-record check written inside the controller action.
Remedy: place `conditional` **after** every middleware that can reject the request; move per-record checks out of the action and into middleware. There is no way to have both the compute saving and the check.
Scope correction that must be stated: a client that holds **no** tag cannot trigger this. A bare `If-None-Match: *` used to short-circuit and made the status code an existence oracle for any id; `Conditional::wildcardOnly()` now refuses to short-circuit a wildcard that is not accompanied by a concretely matching tag, so a wildcard read takes the ordinary path and every gate runs. The remaining exposure is a client that legitimately obtained a tag and later lost access.
Verified by: `tests/Feature/AuthorizationOrderingTest.php`; `integration-findings-v02.md` F2 for the closed wildcard case.
Note in the entry that `ThrottleRequests` specifically **cannot** be bypassed this way, and why: it sits at priority index 7 and `SubstituteBindings` at index 10, and the short-circuit needs bindings, so throttling is always already outside it. A *custom* limiter that is not priority-listed is not protected by that accident.

**H2 — `terminate()` runs even though `handle()` did not.**
Fact: `Illuminate\Foundation\Http\Kernel::terminateMiddleware()` calls `terminate()` on everything `gatherRouteMiddleware()` returns, whether or not it executed. On a short-circuited `304` a terminable middleware declared after `conditional` gets its teardown with none of the state its `handle()` would have set.
Remedy: declare terminable middleware **outside** `conditional`, or make `terminate()` tolerate its own state being absent.
State the Octane amplification: on a long-lived worker the leftover state is not null, it is the previous request's.
Verified by: `integration-findings-v02.md` F5, which reproduced a request timer reporting `microtime(true) - null`.

**H3 — A `version` column must change on every single write.**
Fact: `HasConditionalValidator::conditionalVersionColumns()` returns `['version', <the updated_at column>]` and `conditionalVersion()` takes the first non-empty value in that order — so a column literally named `version` wins over `updated_at` unconditionally.
Three shapes to state: a pre-existing `version` that means something else (a document revision label, a schema version, a counter only some paths bump) freezes the tag; a **nullable** one splits the table, tracking `updated_at` on null rows and the column on populated ones, so backfilling it once silently stops those rows tracking edits; and soft deletes bump `deleted_at` and `updated_at` but never `version`.
Remedy: override `conditionalVersionColumns()` to point at something that means *this row changed*.

**H4 — On a nested route the first bound model wins.**
Fact: `ModelStrategy::target()` iterates `$route->parameters()` — which keep their declaration order — and returns the first one implementing `ProvidesConditionalValidator`.
Two consequences to state concretely: on `/articles/{article}/comments/{comment}` the tag tracks the article, so editing the comment never moves it; on `/{tenant}/articles/{article}` every article under a tenant shares the tenant's single tag.
Remedy: implement the contract only on the record the route actually represents, or override `conditionalValidator()` on the outer record to fold the inner one's version in.
Say that first-wins is deliberate — deterministic beats clever, and the target never moves with runtime state.
Verified by: `integration-findings-v02.md`, "First-parameter-wins staleness".

**H5 — A model-derived tag is scoped to the record and to nothing else.**
Fact: the default fingerprint is `[connection database name, connection table prefix, table, key, version]`, assembled in `HasConditionalValidator::conditionalLocation()` and `conditionalVersion()`. Nothing about the viewer, the tenant row, or the representation is in it.
Under `body` this came free — the tag was a hash of the bytes actually sent. Under `model` it does not.
Three cases, stated separately:
- **Viewer.** A route where an admin sees extra fields collapses every viewer to one tag; a tag minted for the admin is then honoured for anyone who presents it.
- **Tenant.** Database-per-tenant and prefix-per-tenant **are** separated, because the database name and the prefix are both in the fingerprint. **Single-database row-level tenancy is not** — one database, one prefix, one table, so tenant A's row 1 at version 1 and tenant B's produce the same tag. State both halves; the covered half is as important as the uncovered one.
- **Representation.** Content negotiation, sparse fieldsets, `?include=`. Verified concretely: one URL served `<h1>Changed</h1>` to `Accept: text/html` and `{"id":1,…}` to `Accept: application/json` under an **identical strong ETag with no `Vary` header**.
Remedy: override `conditionalValidator()` and fold the request-dependent input into the tag. Reuse the existing README example; it must pass `lastModified` through (see H-adjacent note in Task 4, Step 6).

**H6 — A short-circuited `304` substitutes a `Cache-Control` your application did not choose.**
Fact: `Conditional::notModified()` builds `new IlluminateResponse`, which carries Symfony's default `Cache-Control: no-cache, private`. Middleware that skips empty responses — Laravel's own `SetCacheHeaders` returns early for a contentless non-`HEAD`, non-binary, non-streamed response — never applies the application's policy to it.
Consequence: RFC 9111 §4.3.4 requires a cache to update its stored headers from the `304`, so the first successful revalidation permanently downgrades a `public, max-age=60` entry to `private` (out of every shared cache) and sets `no-cache` (revalidate every time). The caching policy destroys itself on first use.
Remedy: set cache headers from middleware declared **inside** `conditional` — a header already on the response before `setNotModified()` survives, because Symfony does not strip `Cache-Control`.
Nuance that must be stated or the entry is misleading: middleware that sets headers *unconditionally* on the way out survives regardless of position; it is specifically middleware that skips empty responses that loses them.
Verified by: `integration-findings-v02.md` F3, both arrangements.

**H7 — Response-mutating middleware outside `conditional` breaks the tag↔bytes contract.**
Fact: `Conditional::attach()` hashes `$response->getContent()` at `conditional`'s own position in the stack. Global middleware always run outside route middleware, so an HTML minifier, a CSP-nonce injector, a CSRF token refresher, or a debug bar mutates the body after the hash was taken.
Consequence, stated with the reproduction: one strong ETag was served with three different bodies; a client revalidating with that tag gets `304` every time and pins the first CSP nonce for ever while the server keeps generating new ones. For an embedded CSRF token it breaks every form on the cached page.
Remedy: declare body-mutating middleware **inside** `conditional`, or exclude those routes with the `exclude` config key.
Verified by: `integration-findings-v02.md` F6, including the route-level mirror where `['wrap:…', 'conditional']` served the pre-mutation hash and `['conditional', 'wrap:…']` was correct.

**H8 — A reverse proxy rewrites or drops the tag when it compresses.**
Fact: nginx drops `ETag` outright when it gzips; Apache appends `-gzip`. Either way the tag the client holds is not the tag this middleware computed.
Remedy / diagnostic: `curl -sI -H 'Accept-Encoding: gzip' <url>` against the proxy and against the application directly shows the difference immediately. If `304`s work in development and never in production, check this first.
Not verified in-repo — no proxy in the integration harness. Say so.

**H9 — `lock` runs your controller inside a transaction.**
Fact: `Conditional::locked()` wraps `$next()` in `Connection::transaction()` on the target record's own connection, with one attempt.
Six consequences, each one line: everything the controller does is in one unit of work; a job dispatched inside it runs **before** the commit unless `afterCommit()` is set; the row stays locked for the controller's whole duration, so a slow guarded route is a queue of waiting writers; **an error response is not a rollback** — returning a `500` commits, exactly as inside a hand-written `DB::transaction()`, because `Connection::transaction()` inspects control flow and not status codes; only the target row on only that connection is locked; and a wait that exceeds `lock_timeout` is answered `503` with `Retry-After`.
Remedy: keep guarded routes lean; use `dispatch($job)->afterCommit()`; throw rather than return when you want work discarded; catch `LockTimeoutException` to answer a busy row differently.
Nested transactions savepoint, which is fine and is covered by test.

**H10 — `lock` takes no lock on SQLite.**
Fact: `SQLiteGrammar::compileLock()` returns the empty string, so `lockForUpdate()` compiles to nothing. The re-read and the re-evaluation still happen and still catch a competitor who has already committed, but there is no exclusion and the window between the re-read and the write stays open.
Remedy: use MySQL, MariaDB, PostgreSQL, or SQL Server for routes that need the guarantee.

**H11 — An `ETag` already on the response turns everything off.**
Fact: `Conditional::eligible()` returns `false` when `$response->getEtag() !== null`. That rule exists so the package never overwrites a tag the application chose — but it also means that response takes no part in `304` handling at all.
The sharp case: `['conditional:model', 'cache.headers:public;max_age=60;etag']`. The inner middleware sets a body-hash tag first, `conditional` then declines, and the route advertises a tag the model short-circuit can never match — so you asked for the compute-saving strategy and silently got the bandwidth-only one, with the controller running on every request.
Remedy: do not combine `conditional` with anything else that sets an `ETag` on the same route; if you must, put the other one outside.
Verified by: `integration-findings-v02.md` F7, where a controller hit counter proved the controller ran on every `304`.

**H12 — Kernel-global placement changes two things.**
This is the one entry that describes unfixed defects. Say so plainly.
Fact one: under global placement nothing re-`prepare()`s a `304` the middleware manufactured, so Symfony's `Response::prepare()` never runs its `ini_set('default_mimetype', '')` guard and PHP's SAPI adds `Content-type: text/html; charset=UTF-8` to the `304`. Under RFC 9111 §4.3.4 a cache holding an `application/json` `200` overwrites its stored `Content-Type` with that on the first revalidation. Reproduced on the CLI SAPI; the mechanism is a PHP ini default so php-fpm and mod_php are expected to match, unverified. Octane and RoadRunner do not go through PHP's SAPI header layer and are not affected.
Fact two: under the `body` strategy `Conditional::handle()` sets `$request->setMethod('GET')` for a `HEAD`, and under global placement that happens **before routing** — so a `Route::match(['HEAD'], …)` route is looked up as a `GET` and answers `405`. Ordinary `Route::get()` routes already answer `HEAD`, so the blast radius is small, but it is a middleware silently changing routing behaviour.
Remedy: prefer route or group placement. Global placement remains supported — the exclusion re-check after `$next()` exists specifically for it — but these two are its price.
Verified by: `integration-findings-v02.md` F1 and F4.

**H13 — A bad `strategy` or `hash` value is a per-request `500`, not a degradation.**
Fact: `ConditionalRequests::strategy()` throws `InvalidArgumentException` naming the unregistered name and listing the registered ones; `BodyHashStrategy::__construct()` throws when `hash_algos()` does not contain the algorithm, and it is constructed before `$next()` so the failure now reaches requests that end in a `404`, a stream, or an oversized body. Flag matching is **case-sensitive** — `conditional:MODEL` is an unregistered strategy name and `500`s.
There is no boot-time validation. A typo in a published config file takes down every conditional route.
Remedy: cover at least one conditional route in a smoke test that runs on deploy; treat this config file as deploy-critical.
Verified by: `integration-findings-v02.md` F8.

**H14 — `xxh128` is not collision-resistant against a chosen input.**
Fact: design §6. The default is a change-detection fingerprint, not a security primitive. If response bodies carry attacker-influenced content *and* serving a stale representation matters, a crafted body can be made to collide with an earlier one and suppress the client's refresh.
Remedy: set `hash` to a cryptographic algorithm. Collision from *incidental* change is irrelevant at this scale and is not the concern.

**H15 — `extend()` outside a provider's `boot()` mutates shared state permanently.**
Fact: the registry is a container singleton (`ConditionalRequestsServiceProvider::register()`). Calling `extend()` from a controller, a route closure, or any other request handler mutates it for the rest of the process — under Octane, for the whole worker and every subsequent request it serves.
Remedy: call it from a service provider's `boot()` only.

**H16 — A cast primary key silently produces no validator at all.**
Fact: `HasConditionalValidator::conditionalValidator()` returns `null` unless `getKey()` yields a `string` or an `int`. `getKey()` returns the **cast** value, so an enum cast or a value-object cast on the primary key produces no validator — the route gets no `ETag` and no error.
Remedy: override `conditionalValidator()` to supply the raw key yourself.
Say that it fails safe but silently, which is the problem.

**H17 — One-second granularity, on both validators.**
Fact one: `updated_at` is stored to the second by default, so two writes inside one second produce the same tag. Verified concretely: two saves in one second on a `datetime` column produced byte-identical tags with different titles.
Fact two: `Last-Modified` is an HTTP-date and has whole-second resolution that widening the column cannot fix, which is why the package **withholds the header until the second holding the change has elapsed** — see [`reads.md`](reads.md#last-modified-and-if-modified-since).
Remedy: add a `version` column, or widen the column's precision, for resources that change that fast. Note that widening helps the `ETag` and cannot help `Last-Modified`.

**H18 — Under `body`, your controller sees `GET` for a `HEAD` request.**
Fact: `Conditional::handle()` sets `$request->setMethod('GET')` around `$next()` when the strategy has not already produced a validator, because `Router::runRouteWithinStack()`'s pipeline destination calls `prepareResponse()` (Router.php:821) *before* route middleware regains control, and Symfony's `Response::prepare()` nulls the body for `HEAD` there — leaving nothing to hash. The method is restored in a `finally`.
Consequence: controller code calling `$request->method()` or `isMethod('HEAD')` sees `GET` for the duration of that call.
Under a request-derived strategy such as `model` there is no body to hash and nothing is mutated.
Remedy: use `model`, or do not branch on the method inside a `conditional`-wrapped action.

- [ ] **Step 2: Write the reference table**

The facts each row must carry:

- `enabled` — bool, `true`. Master switch. `false` is a true pass-through: no validator, no method mutation, and the write path is suppressed too. Verified: `Conditional::requestEligible()` returns early.
- `strategy` — string, `'body'`. The strategy used when a route names none. A middleware flag always wins. An unregistered name is a per-request `500` → [H13](hazards.md#h13).
- `hash` — string, `'xxh128'`. Any algorithm `hash()` accepts. Used by `body` only; `model` derives its tag from the record. Not a security primitive → [H14](hazards.md#h14). An unsupported value is a per-request `500`, raised on every eligible request since the strategy is constructed before `$next()`.
- `weak` — bool, `false`. Emits `W/"…"`. **Pairing this with `required` throws a `LogicException`** — a weak validator can never satisfy `If-Match`.
- `max_response_bytes` — int, `1_048_576`. Read path, body-derived validators only. `0` or negative means unlimited. Suppressed entirely when the strategy already answered from the request.
- `methods` — list of strings, `['GET', 'HEAD']`. **Read path only.** Adding an unsafe method here does not attach validators to its responses, and removing one does not disable the write path. Case-insensitive — the middleware upper-cases them.
- `exclude` — list of strings, `[]`. Route names or URI patterns, both with `*` wildcards. Suppresses **both** paths. This is the key to reach for when a route must opt out entirely.
- `last_modified` — bool, `true`. Governs emission of the header **and** the `If-Unmodified-Since` fallback together: with it off, responses carry no date and `If-Unmodified-Since` is refused rather than ignored.
- `lock_timeout` — int, `5`. Seconds to wait for a row before `503`. Applied on PostgreSQL (`SET LOCAL lock_timeout`) and MySQL/MariaDB (`SET SESSION innodb_lock_wait_timeout`, restored afterwards); other drivers ignore it. `0` leaves the server's own setting alone — and PostgreSQL's own default is `0`, meaning wait for ever.

Add one line under the table recording a coercion fact the sweep verified, because it saves a support round trip: a bare string where a list is documented degrades to a single-element list rather than a `TypeError`, and a `null` or non-numeric `max_response_bytes` reads as unlimited.

### Task 7: The migration guide

The most valuable artefact in this release. `werk365/etagconditionals` has roughly 280,000 installs and is the package this one exists to replace, so the guide has to be more useful to a migrator than the incumbent's own README — and more honest, which is the easier of the two.

Design §11 is the backbone: §11.1 is the parity baseline, §11.2 is the thirteen-defect table, §11.3 is three of the cutover differences. This task adds nine more that §11.3 does not have, all of them read out of the incumbent's source rather than its documentation.

**The incumbent's source is the authority for every claim about it.** A copy is available at `.../scratchpad/werk365/`. The facts this task depends on, all verified there:

- `EtagConditionalsServiceProvider::boot()` registers the group `etag` as `[SetEtag, IfNoneMatch, IfMatch]` and aliases each middleware by its own `$middleware` property — `setEtag`, `ifNoneMatch`, `ifMatch`.
- `SetEtag::handle()` calls `$response->setEtag(EtagConditionals::getEtag(...))` **unconditionally** — every status, every response, and over an application-set tag.
- `EtagConditionals::defaultGetEtag()` is `md5($response->getContent())`, wrapped by `Str::of($etag)->start('"')->finish('"')`.
- `IfNoneMatch::handle()` compares with `in_array($etag, $request->getETags())` and calls `$response->setNotModified()` on a hit, with no status check.
- `IfMatch::handle()` returns early unless `$request->isMethod('PATCH') && $request->hasHeader('If-Match')`.
- `IfMatch` re-dispatches an internal `GET` through `app()->handle()`, copying the request's headers and adding `X-From-Middleware: IfMatch`, then calls `app()->instance('request', $request)`.
- `IfMatch` tests the wildcard as `in_array('"*"', $ifMatchArray)` — a **quoted** wildcard.
- `config/etagconditionals.php` is `['if_match_weak' => env('IF_MATCH_WEAK', true), 'if_none_match_weak' => env('IF_NONE_MATCH_WEAK', true)]`, and both strip `W/` from the **client's** tags only.
- `composer.json` requires `illuminate/support: ~7|~8|~9|~10|~11|~12` and declares **no `php` constraint**.

- [ ] **Step 1: Write "Should you migrate?"**

Three short paragraphs and a decision line. The honest framing, which the rest of the page has to live up to:

> You should migrate if you need the **write** half. `If-Match` on every unsafe method, `428` so clients cannot opt out by omitting a header, an `If-None-Match: *` create guard, and a `lock` mode that actually closes the check-then-write race are the reasons this package exists. The incumbent guards `PATCH` only, returns early when the header is absent, and has no lock.
>
> You should migrate if you need `Last-Modified`, `If-Modified-Since`, or `If-Unmodified-Since`. The incumbent implements none of the three.
>
> You should migrate if the incumbent's internal `GET` re-dispatch is costing you. It runs the entire kernel a second time for every guarded write — middleware, auth, controller, serialization — and needs an `X-From-Middleware` sentinel that your own middleware has to special-case.

Then the decision line, which must appear before the mapping table and not after it:

> If none of those describe you, read [When not to migrate](#when-not-to-migrate) first.

- [ ] **Step 2: Write "When not to migrate"**

This section is the reason a reader will trust the rest of the page. It must be specific enough to actually talk someone out of it.

Five cases, each with the reason:

- **You use `setEtag` plus `ifNoneMatch` on a small JSON API, it works, and you have no lost-update problem.** Then don't. You would trade a working three-middleware install for a config file, a one-time cache-invalidation storm across every client, and — if you want any of the write path — a contract and a trait on your models. In exchange you get a 1 MiB size ceiling, skip rules for streamed and binary responses, and a faster hash. Those are real, and they are small. This is the case the guide exists to be honest about.
- **Your models have no column that reliably means "this row changed", and you cannot add one.** The write path is derived from the record's version, not from the response body. Without a `version` column or trustworthy timestamps there is nothing to guard with. See [H3](hazards.md#h3).
- **You are on PHP below 8.3 or Laravel below 12.** The incumbent runs on Laravel 7 through 12 and declares no PHP constraint at all; this package requires `^8.3` and `^12.0||^13.0`. There is no backport.
- **You rely on tags being attached to non-2xx responses.** `SetEtag` hashes every response it sees. This package tags 2xx only, deliberately, and it is not configurable.
- **Something downstream treats a change of ETag algorithm as a failure** rather than as a cache miss. Migration invalidates every stored tag once. That is normally a single expensive request per client; if it is not, find out why before you deploy.

Close with one line that does not oversell: migrating for the read path alone is a lateral move. Migrate for the write path.

- [ ] **Step 5: Write "What changes in behaviour on day one"**

A numbered list, each item in the shape *what changes → who it hits → what to do*. Twelve items. Three are §11.3; the rest were read out of the incumbent's source for this guide.

1. **Responses over 1 MiB stop being tagged.** `max_response_bytes` defaults to `1_048_576`; the incumbent has no ceiling. A route that used to `304` silently stops. → Set `max_response_bytes => 0`, or accept it and know which routes are affected.
2. **Only 2xx responses are tagged.** `SetEtag` hashes every response, including 3xx, 4xx and 5xx. → Not avoidable. A validator on an error response is meaningless, and this is deliberate.
3. **`xxh128` invalidates every client's cached tag, once.** The first request after deploy is a full `200` even for unchanged content, for every client. → `hash => 'md5'` preserves existing tags byte-for-byte and avoids the storm entirely.
4. **`If-Match` uses strong comparison.** Their `if_match_weak` defaults to `true`, which strips `W/` from the client's tags. A client sending `W/"abc"` on a `PATCH` succeeded before and gets `412` now. → There is no configuration for this; §13.1.1 requires it. Fix the client — a weak validator genuinely cannot support an update guard.
5. **Every unsafe method is guarded, not just `PATCH`.** A stale `If-Match` on a `POST`, `PUT` or `DELETE` used to be ignored and is now `412`. → This is defect #1 and MDN's canonical mid-air-collision example is a wiki save over `POST`. Audit which clients send `If-Match` on non-`PATCH` writes before you deploy.
6. **A missing precondition can now be refused.** Under `conditional:required`, an unsafe request with no `If-Match`, no `If-Unmodified-Since` and no `If-None-Match` gets `428` — where the incumbent returned early and let it through. This will reject clients that previously succeeded by omitting the header. → Deploy in two steps: plain `conditional` first, watch your logs for which clients actually send a precondition, then add `required` per route once you know. `required` is per-route by design and there is no global switch, which makes the staged rollout the natural one.
7. **`If-None-Match: *` on a read starts producing `304`.** The incumbent compares `in_array($etag, $request->getETags())`, and `'*'` never equals a quoted tag, so a wildcard read returned `200` with the body. Symfony treats `*` as matching any validator, so it returns `304` here. → A client sending a wildcard on a `GET` starts getting empty responses. Note that this package refuses to answer a bare wildcard *before* the controller, so no gate is skipped — but the status code does change.
8. **An error response can no longer become a `304`.** `IfNoneMatch` calls `setNotModified()` without checking the status, so a `404` or a `500` whose body happened to hash to the client's tag became a `304`. Here, `Conditional::eligible()` requires `isSuccessful()`. → Strictly an improvement; listed because it is a behaviour change.
9. **An application-set `ETag` is now preserved and ignored, rather than overwritten and honoured.** `SetEtag` overwrites unconditionally. This package leaves your tag alone — and that response then takes no part in `304` handling at all. → If any route sets its own tag, its behaviour inverts. See [H11](hazards.md#h11).
10. **The internal `GET` re-dispatch is gone.** Anything that depended on it stops: a controller that logged reads is no longer invoked twice, a rate limiter no longer counts a synthetic `GET`, the `X-From-Middleware` header is never sent. Your guarded write route also no longer needs a `GET` counterpart to exist at all. → Remove the sentinel handling from your own middleware. Check your metrics before you conclude read traffic has dropped.
11. **The write path needs the `model` strategy, and therefore a contract on your models.** `required` and `lock` imply `model`, because the current validator must be known before the controller runs and a body hash cannot supply one. The incumbent needed no model changes at all. → This is the largest single item on this list. Budget for it.
12. **Model-derived routes start emitting `Last-Modified`.** Clients that send `If-Modified-Since` behave differently from before, when the header never appeared. The date is withheld until the second holding the change has elapsed — see [`reads.md`](reads.md#last-modified-and-if-modified-since) for why. → Set `last_modified => false` to keep the family out of the conversation.

- [ ] **Step 1: Delete the facade**

The reasoning, which goes into the commit message and into `docs/api.md`:

The facade fronts `ConditionalRequests`, a registry with two methods. `strategy()` is called by the middleware and by nobody else. `extend()` is called once per custom strategy, from a service provider's `boot()`. So the facade's entire real surface is one boot-time call — and a facade is precisely the tool that makes that call effortless from a controller, a route closure, or a request handler, which is exactly what the documentation already forbids because the registry is a container singleton and Octane keeps it for the life of the worker ([H15](hazards.md#h15)).

Three further costs. It claims a global class alias `ConditionalRequests` in every consuming application's root namespace, through `extra.laravel.aliases`, for that one call. It collides by short name with the class it fronts — `ExpertSystems\ConditionalRequests\ConditionalRequests` and `ExpertSystems\ConditionalRequests\Facades\ConditionalRequests` — badly enough that the facade's own source has to write the target's FQCN inline, and badly enough that a user will import the wrong one. And it carries no `@method` annotations, so at PHPStan level 7 with 100% type coverage it is the one public entry point the analysis cannot see through.

The replacement is shorter than the facade call and is typed:

```php
public function boot(ConditionalRequests $conditional): void
{
    $conditional->extend('revision', fn (): ValidatorStrategy => new RevisionStrategy);
}
```

No tags exist and nothing has been published to Packagist, so removing it now costs nothing to any released consumer. After 1.0 it would cost a major version.

```bash
git rm src/Facades/ConditionalRequests.php
rmdir src/Facades
```

        "laravel": {
            "providers": [

- **The middleware** — the alias `conditional`, the flags (`body`, `model`, any registered strategy name, `required`, `lock`), their order-independence, and the class name `Http\Middleware\Conditional` so it can be named in `withoutMiddleware()` and in a kernel-global registration. **Its constructor signature is explicitly not frozen** — it gained parameters in v0.3, v0.4 and v0.5 and is resolved from the container. Say so; it is the distinction that keeps the middleware extensible without breaking the promise.
- **Exceptions** — `Exceptions\PreconditionFailedException` (412), `Exceptions\PreconditionRequiredException` (428), `Exceptions\LockTimeoutException` (503), their parent Symfony classes (which is what an application catches), and their `MESSAGE_KEY` constants.
- **Configuration keys** — all nine, by name. Their **defaults are not frozen**; a default may change in a minor release when the current one is wrong, and the changelog will say so. The key names and their meanings are frozen.
- **Publish tags and translation keys** — the four tags and the three message keys.

```yaml
# This workflow exists because the `lock` mode's mutual-exclusion guarantee
# cannot be proved on SQLite at any effort: SQLiteGrammar::compileLock()
# returns the empty string and SQLite has no row locks. The `tests` workflow
# covers everything else.
#
# Cost, per push and per pull request:
#   - 2 jobs beyond the 24 in `tests`.
#   - Each pulls one database service image (mysql:8.4 ~600 MB,
#     postgres:17 ~430 MB) and waits on its health check before PHP starts.
#   - One `composer update` and one `composer test:lock` per job.
#   - One PHP version only, 8.3. This suite tests database behaviour, not PHP
#     behaviour, and running it across three PHP versions would triple the
#     bill for no additional coverage.
#
# On a public repository the runner minutes are free. On a private one this is
# roughly two extra runner-minutes per push, plus image pull time.
```

- [ ] **Step 3: Split the matrix into two jobs**

v0.5's workflow declares **both** service containers on a single matrix job, so every leg starts a MySQL *and* a PostgreSQL container and waits on both health checks, while using one. Split it into two jobs, `mysql` and `pgsql`, each declaring only its own service. GitHub Actions has no `if:` on a `services:` block, so a matrix cannot express this — two jobs is the only way.

Each job keeps the `Checkout`, `Setup PHP`, `Install dependencies` and `Row lock contention` steps unchanged, including the `pdo_mysql, pdo_pgsql` extensions (both are cheap and keeping the two jobs' PHP setup identical avoids a class of drift), and the same `CONDITIONAL_LOCK_*` environment block with the driver's own values.

This halves the image pulls and removes a health-check wait from each job.

- [ ] **Step 4: Fold the skip guard into the run**

v0.5's final step runs `composer test:lock` a **second time** to grep its output for "skipped". That doubles the database work in every job for a check that costs nothing when done in the same run. Replace both the `Row lock contention` step and the guard with one step:

```yaml
      - name: Row lock contention
        env:
          CONDITIONAL_LOCK_DRIVER: mysql
          # …the rest of the driver's environment
        run: |
          set -o pipefail
          composer test:lock 2>&1 | tee lock.log
          if grep -qi 'skipped' lock.log; then
            echo "The contention suite skipped — the gate did not see its environment."
            exit 1
          fi
```

`set -o pipefail` matters: without it the pipe through `tee` swallows a non-zero exit from Pest and the job would pass on a failing suite while still catching a skip. Keep the guard — a gated suite that silently skips in CI is exactly as useless as no suite — but run it once.

Every `uses:` in this repository is pinned to a commit SHA. The service images v0.5 introduces are pinned to floating tags, `mysql:8.4` and `postgres:17`, which is a weaker posture than the rest of the file for the same class of supply-chain risk.

```bash

docker buildx imagetools inspect postgres:17 --format '{{.Manifest.Digest}}'
```

then write `image: mysql@sha256:…` with the human tag in a trailing comment. If Docker is unavailable in the working environment, leave the tags in place and add a `TODO` comment naming this step rather than guessing a digest — a wrong digest is a broken workflow and a right-looking wrong one is worse.

- [ ] **Step 6: Check the Windows leg against v0.5's SQLite proof**

## Deliberately Out of Scope

Per the phase brief:

- **Any new runtime feature.** The only `src/` changes are one deletion, one `final`, and five docblocks.
- **`Range` / `If-Range`** — a permanent non-goal per design §10.
- **Server-side response caching** — this package validates, it does not store.

Considered and deliberately not done:

- **Fixing F1 and F4, the two kernel-global-placement defects.** A `304` manufactured under global placement picks up PHP's `default_mimetype` because nothing re-`prepare()`s it, and a `HEAD` under `body` is routed as a `GET` before routing happens. Both are real, both are documented as [H12](hazards.md#h12), and both are fixable — the first by calling `$response->prepare($request)` on the short-circuit path, the second by deferring the method mutation until a route exists. Neither is done here because this phase's brief is documentation, migration and the freeze, and a middleware behaviour change on the way into a stable release is the wrong thing to slip in unreviewed. They are the first two items in the list below.
- **Boot-time configuration validation.** F8 makes a typo in `strategy` or `hash` a per-request `500` across every conditional route rather than a degradation to no caching. v0.3 already recorded why a boot-time route scan is the wrong shape — it cannot see controller-declared middleware and it costs a route-collection walk per request. A validating `php artisan conditional:check` command would be the right shape and is a new runtime feature, so it is out of scope here.
- **Retroactively tagging `v0.1.0` through `v0.5.0`.** It would publish five pre-releases nobody should install to make a changelog literally true. See Task 10.
- **An `UPGRADING.md` at 1.0.** Nothing to upgrade from. See Task 10, Step 3.
- **Splitting the documentation into a hosted site.** Eight markdown files in `docs/` render on GitHub, work offline, are diffable in review, and are versioned with the code they describe. A static site is a maintenance surface this package does not need at 1.0.
- **`@method` annotations on the facade.** The facade is deleted instead. Annotating it would have fixed the PHPStan blindness and none of the other three objections.
- **Making `ModelStrategy` non-final so `lockingQuery()` can be overridden.** That would freeze a protected surface for a case one decoration example covers, and `readonly` inheritance rules would constrain the subclass anyway.
- **A `docs/testing.md` for consumers** — how to assert `304`s and `412`s in an application's own test suite. Genuinely useful and genuinely a fourth deliverable. It is additive after 1.0 and blocks nothing.
